# Seed Data Provenance

This project bundles a generated azkar dataset:

- `muslim_data.tsv`

## Source Dataset

- Source: Muslim Data Azkars dataset
- Repository: https://github.com/my-prayers/muslim-data-android
- Commit pinned: `f7968b8765bfa23706751edadc3fed2fa17a9864`
- Dataset artifact used: `muslim-data/src/main/assets/database/muslim_db_v2.5.1.db`
- License: Apache License 2.0

## Transformation

The dataset is generated by:

- `scripts/generate_seed_migration.main.kts`

Transformation rules:

- imports Arabic and English only (`ar`, `en`)
- writes one tab separated line per remembrance, holding the source label, the Arabic and English
  text, the Arabic and English explanation, and the tag names separated by `|`
- sets `grade = UNSPECIFIED`
- creates dataset/category tags and heuristic `Morning`/`Evening` tags
- deduplicates by Arabic text during generation
- falls back to a placeholder explanation when the source dataset carries no reference

## Runtime

`com.azkar.data.seed.SeedDataLoader` reads the file and inserts it with Exposed `batchInsert`
statements inside the transaction `com.azkar.data.config.migrateToLatestSchema` opens. It is a no-op
once the `remembrance` table holds a row, so the dataset is applied at most once per database.

## Reproducibility

Regenerate the dataset by running the script, either from the IDE or from a Kotlin distribution
(Kotlin 2.4.20 or newer):

```bash
kotlinc -script scripts/generate_seed_migration.main.kts
# or, thanks to the shebang line and the execute bit:
./scripts/generate_seed_migration.main.kts
```

Run it from the repository root, because the output path is resolved against the working directory.
Its classpath comes from `@file:DependsOn` (Ktor client, `sqlite-jdbc`), which the Kotlin compiler
resolves from Maven Central on the first run. Only the pinned dataset itself is downloaded
afterwards, at run time.

Then run the app or the tests; the loader picks the file up on the next start.
